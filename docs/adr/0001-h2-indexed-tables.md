# Preserve indexed-table failure semantics on H2

Support unchanged `values[a]` syntax for fixed-length integer and Boolean parameter tables, and reject the execution result when an index is invalid. The user prefers Qamomile-local maintenance and the latest stable converter compatible with Python 3.11, which is hugr-qir 0.1.2. The user selected the first option and requested implementation on 2026-10-28.

Use an H2-specific entry guard and range-proof transformation for shot-derived expressions. Resolve `shot_origin` internally from the destination, prove supported index intervals before submission, and guard the raw device range before quantum operations. This reduces the need to unwind live quantum resources, but deliberately excludes unproved index expressions.

Apply the transformation to an execution copy immediately before `to_h2_qir`. The common lowerer marks classical selections for discovery; the proof follows actual HUGR wires and verifies each selection's bounds predicate and failure-region shape. It does not trust metadata as a safety assertion. Reuse the scalar-selection graph and replace only a proved-unreachable panic with an existing element wire. Retaining this unreachable branch avoids duplicating the selector or adding a general subgraph-moving mechanism.

Check each intermediate UInt64 addition and constant multiplication for overflow. Require fixed bound UInt or Bit elements and reject unknown data sources. Discovery conservatively activates when a module contains both a marked selection and a shot read, even if those are unrelated. Without both, keep the existing path.

Normalize every H2 shot read on an independent execution copy before QIR conversion, using the internal destination origin 1. Apply the entry guard and private success marker even when the program has no table. A converter-rejected abort call enables the limited table proof on the original, unnormalized package; normalize that independently prepared copy once before the final conversion. Never feed the already-normalized copy into table preparation. Programs with their own convertible guards remain accepted without the limited table proof, while their shot reads also become logical zero-based numbers. If no supported table is found, preserve the conversion failure. Proof failures still stop before provider operations. The public options expose neither `h2_shot_origin` nor `shot_origin`. Helios also subtracts an assumed native origin of 1 on its upload copy; this is a selected policy rather than a verified hardware property. H2-specific proof and success-marker handling are not applied to Helios.

The alternatives are whole-program checked-HUGR failure propagation and a structured QIR error-exit transformation. The former supports more index sources at greater compiler complexity. The latter has executable local fixtures but depends on converter output and a proper LLVM graph transformation.

Guarded programs return an internal integer status and a private Boolean success marker. Save the required output name as `shot_success_tag` and the applied numbering offset as `shot_origin`. Verify the named marker for every shot before creating public records; reject missing, malformed, false, or incomplete results. Omit the marker from public records. Restoration reads these saved fields without rerunning conversion or substituting the current destination origin. The marker requirement has no independent version number or legacy guard reader. A locally validated integer return and private success marker do not establish hardware behavior. Keep source programs immutable across execution targets, retain final QIR validation, and never infer a device numbering contract from one recorded run.

Return public Boolean values through the entry guard before recording them. The valid branch returns measured values; the invalid branch supplies false placeholders without running the user body. Record the joined values outside the branch and the success marker last. The mandatory false marker rejects the entire invalid execution before placeholders can become public samples. This avoids a hugr-qir 0.1.2 dominance failure observed when guarded bodies contain multiple conditional X/Y gates. Both HUGR and QIR validation remain enabled; no final QIR rewriting or measurement reconstruction is added.

Reject guarded H2 syntax-checker targets before authentication because their synthetic zero readouts cannot establish the required success marker. Plain syntax-checking remains available for programs without this guard. Keep destination-specific numbering internal rather than exposing an H2-only option to callers.

The [H2 execution tests](../../tests/hugr/test_h2_shot_execution.py) cover normal and failing shot ranges, immutable source programs, and public result restoration. Read-only retrieval of an existing user-submitted H2 job verified successful decoding of all four shots and the private success markers. This does not establish failure reporting on hardware, numbering across job chunks, or a Helios hardware origin. No new provider jobs were submitted by this implementation task.
