# Qamomile v0.16.0

Qamomile v0.16.0では、Pythonで書いた量子プログラムをRustコンパイラで検証します。v0.15.2から移行する場合、主に変わるのは、量子カーネルの実行方法、測定結果の受け取り方、計算に必要な量子ビット数やゲート数の見積もり方です。RC1をお使いの方は、末尾の[RC1からの変更点](#v0160-rc1-changes)をご覧ください。

```bash
pip install qamomile==0.16.0
```

## Rustコンパイラによる検証

v0.15.xでは、`import qamomile.circuit as qmc`で読み込み、量子計算を記述するPython関数に`@qmc.qkernel`を付けて量子カーネルを定義していました。Qamomileはその関数を仮の入力で動かし、呼ばれた操作を記録して回路を組み立てていました。v0.16.0では`import qamomile as qm`でQamomileを読み込み、カーネルに`@qm.qkernel`を付けます。Qamomileがその関数のソースコードを読み取り、Rustコンパイラが値の型や量子状態の受け渡しを検証します。実行先への変換にもリソース推定にも、この検証済みのプログラムを使います。

また、Rust製の組み込みシミュレータとして`qm.Reference()`が加わりました。Qamomileの基本インストールだけで、検証済みの量子プログラムを手元で実行し、測定結果を確認できます。

## 量子カーネルのコンパイルと実行

v0.15.xでは、`QiskitTranspiler`などの実行先ごとの変換器と、実行を担当するExecutorを組み合わせていました。v0.16.0では、`qm.specialize()`で定数を確定し、`qm.compile(..., to=...)`で指定した実行先向けに変換し、`qm.run(..., on=...)`で実行します。

カーネルの引数は、値をいつ決めるかによって書き分けます。コンパイル前に値を固定する引数には`Const`を、実行ごとに値を指定する引数には`Param`を使います。次の例では、同じ`reference`をコンパイル先と実行先の両方に指定します。

```python
import qamomile as qm

@qm.qkernel
def biased_coin(n: qm.Const[qm.Int], theta: qm.Param[qm.Real]) -> qm.Shot[qm.Bits[1]]:
    state = qm.qubits(1)
    for _ in range(n):
        state = qm.ry(state, theta)
    return qm.measure(state)

reference = qm.Reference()
program = qm.specialize(biased_coin, n=3)
artifact = qm.compile(program, to=reference)
record = qm.run(
    artifact, on=reference, parameters={"theta": 0.0}, shots=8, seed=7
)
assert record.result.counts == {(0,): 8}
```

この例では、`qm.specialize(biased_coin, n=3)`で回転の回数を3回に固定し、回転角`theta`は`qm.run()`の`parameters`で渡します。角度が0のとき、測定結果は8回とも`(0,)`です。同じ`artifact`を`parameters={"theta": 0.5}`で実行すると、角度だけを変えて試せます。測定結果のように、1回の試行（ショット）の途中で決まる値は`Shot`で表します。手順を一つずつ試すには、[はじめての量子カーネル](../tutorial/01_your_first_quantum_kernel.ipynb)をご覧ください。

## 測定結果と期待値

v0.15.xでは、複数回の測定に`executable.sample()`を使い、1回の実行やカーネル内の`expval`による期待値計算には`executable.run()`を使っていました。v0.16.0では、`qm.run()`が`RunRecord`（実行条件と結果の記録）を返します。ビット列を繰り返し測定する場合は、`record.result.counts`から測定値ごとの出現回数を取得できます。

観測量の期待値を求めるには、量子状態を準備するカーネルと観測量を`qm.expectation()`に渡します。戻り値から推定値と標準誤差を取得できます。たとえば、ゼロ状態でZを測定すると、測定値は毎回+1になります。

```python
@qm.qkernel
def prepare_zero() -> qm.Q[qm.Bits[1]]:
    return qm.qubits(1)

estimate = qm.expectation(
    prepare_zero, qm.Z(0), on=reference, shots=8, seed=7
)
assert estimate.value == 1.0
assert estimate.standard_error == 0.0
```

## 量子型をアフィン型から線形型へ変更し、自動アンコンピュテーションを導入

v0.15.xでは、`Qubit`や`Vector[Qubit]`を未使用のまま残せました。v0.16.0では量子状態を`Q[T]`で表し、ゲートを適用したら更新後の状態を次の操作に渡します。コンパイラは、各時点の状態が次のゲートや測定、返却、明示的な破棄（`qm.discard()`）などにちょうど1回引き渡されることを検証します。これを線形型の規則と呼びます。

作業用の量子ビットについては、安全に元に戻せるとコンパイラが判断すると、計算を自動で巻き戻して解放します（自動アンコンピュテーション）。次の例では、`scratch`にTの逆ゲート、続いてHゲートを適用して元の状態に戻し、量子ビットを解放します。

```python
@qm.qkernel
def with_scratch() -> qm.Shot[qm.Bits[1]]:
    scratch = qm.qubits(1)
    scratch = qm.h(scratch)
    scratch = qm.t(scratch)
    return qm.measure(qm.prepare((1,)))
```

安全に元に戻せると確認できない状態は、どこへ渡すかを明示します。たとえば、返却する、測定する、`qm.discard()`で破棄するといった選択肢があります。`qm.discard()`は、それまでに適用したゲートを取り消す処理を行いません。

## リソース推定インターフェースの変更

v0.15.xのリソース推定では、量子カーネルの`kernel.estimate_resources()`を呼び出して推定結果を取得していました。v0.16.0では、`qm.resources.logical(program)`に量子プログラムを渡し、戻り値の`ResourceStudy`から必要な指標を選びます。次の例では、論理ゲート数と、同時に使う量子ビット数の最大値を取得します。

```python
study = qm.resources.logical(program)
gates = study.metric(qm.resources.LOGICAL_GATES)
qubits = study.metric(qm.resources.LOGICAL_PEAK_QUBITS)
```

指標には、推定値の上下限や前提条件、値を正確に決められない理由が含まれることもあります。推定結果の読み方は[リソース推定](../tutorial/04_resource_estimation.ipynb)で紹介しています。

## 量子操作の標準ライブラリ

v0.15.xで`qamomile.circuit.algorithm`と`qamomile.circuit.stdlib`に分かれていた量子アルゴリズムの部品と標準関数は、v0.16.0では`qamomile.stdlib`から読み込みます。同じ名前でも、新しい量子型に合わせて引数や戻り値が変わったものがあります。たとえば量子フーリエ変換（`qft`）は、レジスタとその幅を受け取り、変換後のレジスタを返します。

```python
from qamomile.stdlib import qft

@qm.qkernel
def fourier_sample() -> qm.Shot[qm.Bits[2]]:
    state = qm.qubits(2)
    state = qft(state, 2)
    return qm.measure(state)
```

[多次元量子フーリエ変換のチュートリアル](../algorithm/multidimensional_qft.ipynb)では、レジスタをx方向とy方向に分け、それぞれに`qft`を適用します。

## 多項式からQSVTの位相列を生成

v0.15.xで`qsvt()`（量子特異値変換）を使うには、位相列を利用者が用意していました。v0.16.0では、`synthesize_qsvt_polynomial()`にチェビシェフ多項式の係数を渡すと、位相列を生成し、得られた応答の実部が区間$[-1, 1]$で目標の多項式をどれだけ正確に近似するかを検証します。戻り値はそのまま`qsvt()`に渡せます。次の例では、多項式$p(x)=x/2$を誤差$10^{-6}$以下で近似します。

```python
from qamomile.stdlib import synthesize_qsvt_polynomial

polynomial = synthesize_qsvt_polynomial([0.0, 0.5], max_error=1e-6)
assert polynomial.uniform_error_bound <= 1e-6
```

合成できる多項式の偶奇や係数の大きさには制約があります。また、再構成誤差が0のブロックエンコーディング（行列を正規化して量子操作の一部に埋め込む表現）では、最小特異値の正の下限を指定して、`reciprocal_svt()`で逆数関数を近似する変換を作れます。

## SciPy疎配列のブロックエンコーディング

`sparse_access_block_encoding()`に、`csr_array`などのSciPyの疎配列（非ゼロ要素を中心に保持する配列）を直接渡せます。対象は一辺の長さが2以上の2の累乗である正方行列で、複素数や非対称の行列も扱えます。戻り値の`normalization`で正規化係数を、`error_bound`で行列の再構成誤差の上限を確認できます。

この例でSciPyの疎配列を使うには、`qamomile[sparse]`が必要です。

```python
from scipy.sparse import csr_array
from qamomile.stdlib import sparse_access_block_encoding

matrix = csr_array([[1.0, 0.0], [0.0, 0.5]])
encoding = sparse_access_block_encoding(matrix, max_error=1e-8)
assert encoding.error_bound <= 1e-8
```

## QAOAExperimentへの移行

:::{note}
ここで紹介する数理最適化のインターフェースは現在調整中です。`QAOAExperiment`の呼び出し方などは、近いうちに変更する予定です。
:::

v0.15.xで`QAOAConverter`を使っていた場合、v0.16.0では`QAOAExperiment`に問題と回路の設定をまとめます。QAOA（量子近似最適化アルゴリズム）では、問題と層数を固定して一度コンパイルすれば、角度を変えながら実行できます。次の例では1組の角度を試します。角度を探索する例は[QAOAでMax-Cut問題を解く](../algorithm/qaoa_maxcut.ipynb)で紹介しています。

```python
from qamomile.optimization import BinaryModel, QAOAExperiment

model = BinaryModel.from_hubo({(0,): -1.0, (1,): -1.0, (0, 1): 2.0})
experiment = QAOAExperiment(model, layers=1)
compiled = experiment.compile(to=reference)
result = compiled.run(
    on=reference, gammas=[0.0], betas=[0.0], shots=8, seed=7
)
```

[OMMXベンチマークのチュートリアル](../integration/ommx_quantum_benchmarks_qaoa.ipynb)では、同じ二値最適化問題をQAOAと古典ソルバーのSCIPで解き、結果を比較します。

## コンパイラ最適化の設定と拡張

v0.16.0では、コンパイル時に適用する最適化処理とその順序を選べるようになりました。`qm.compile()`の`optimizer`引数に`OptimizationPipeline`を渡します。

```python
from qamomile.compilation import OptimizationPipeline

optimizer = OptimizationPipeline.multilevel(family=False)
optimized = qm.compile(program, to=reference, optimizer=optimizer)
```

`append()`で独自の処理を追加し、`replace()`で既存の処理を差し替えられます。変換後のプログラムの型と構造はRust側で検証します。独自の変換を実装した場合、変換の前後で計算結果が保たれることは実装者が確認します。

## Cirqでの実行とQIR出力

Cirq向けにカーネルを変換・実行できるようになりました。次の例では、`qm.run()`に渡す実行先を変えて、最初に定義した`program`をCirqのシミュレータで実行します。

Cirqシミュレータを使うこの例には、`qamomile[cirq]`が必要です。

```python
from qamomile.cirq import CirqSimulator

cirq_record = qm.run(
    program, on=CirqSimulator(),
    parameters={"theta": 0.0}, shots=8, seed=7,
)
```

回路を外部のツールに渡したい場合は、QIR（量子プログラムを表す中間形式）を変換先に指定し、`load_ir()`でテキストを取り出せます。

この例でQIRを出力するには、`qamomile[qir]`が必要です。

```python
from qamomile.qir import QIR, load_ir

qir_artifact = qm.compile(fourier_sample, to=QIR())
qir_text = load_ir(qir_artifact)
```

出力できるのは、回路の構造が事前に決まるQIR 1.0 Base Profileです。実行時パラメータ、測定結果に応じた分岐、測定後のゲートには対応していません。

## RC1からの変更点

[v0.16.0 RC1](v0_16_0_rc1)から移行する場合は、既存のコードや保存済みのプログラムについて次の点を確認してください。

- **1ビットの測定結果が整数になります。** `Q[Bool]`の状態を`measure()`や`measure_reset()`で測ったとき、Python側で受け取る測定値は整数の`0`または`1`です。`measure_x()`、`measure_y()`、`measure_z()`で得られる測定値も同様です。そのビットを返すカーネルの型注釈は`qm.Shot[qm.Bool]`から`qm.Shot[qm.Bit]`に変更してください。この測定結果を真偽値として宣言した保存済みプログラムは、ソースコードから作り直してください。過去に保存した測定結果は、当時の真偽値のまま読み込めます。
- **乱数の種を省略したときの動作が変わります。** 既定値が`seed=0`から`seed=None`になり、省略すると実行先の設定に従います。`qm.Reference()`などのシミュレータでRC1と同じ設定を再現したい場合は、`seed=0`を明示してください。`QurationLocal`では整数の指定が必要です。乱数の種を指定できない実行先では`None`を使います。
- **回転を含む保存済みの回路は再コンパイルが必要です。** 回路を実行する前に、計算後の角度が有限の値であることを検証します。RC1で保存したコンパイル済みの回路にもこの検証を加えるには、元のソースコードからコンパイルし直してください。
- **IBM Runtimeを使う場合**、`qamomile[qiskit]`が必要とする`qiskit-ibm-runtime`のバージョンは0.51以上1.0未満になりました。RC1で`qamomile[qbraid]`を通じてIBM Runtimeもインストールしていた場合は、`qamomile[qiskit]`も指定してください。
- **カーネル内で試行番号を取得できます。** `qm.get_current_shot()`は、各実行の最初の試行で0を返します。次の例では、5回の試行のうち最初の1回だけが`True`を返します。

  ```python
  @qm.qkernel
  def first_shot() -> qm.Shot[qm.Bool]:
      return qm.get_current_shot() == 0

  result = qm.run(first_shot, on=qm.Reference(), shots=5).result
  assert result.values == {True: 1, False: 4}
  ```

- **IBM Runtimeでジョブを事前検証できます。** 対象プランのIBM Quantumアカウントでは、`IBMRuntime(backend=backend, dry_run=True)`を指定すると、量子プロセッサの利用時間を消費せず、測定用のジョブをIBMのクラウドで事前に検証できます。対応する実行モードは単独のジョブとBatch（一括実行）です。

  コンパイル済みの回路を`qm.execute()`に渡すと、検証レポート（`ValidationResult`）が直接返ります。`qm.run()`を使った場合は戻り値の`record.result`から、`qm.submit()`でジョブを送信した場合は`job.result()`で同じレポートを取得できます。レポートの`metadata()["usage"]`で、実機を使った場合の推定利用時間などを確認できます。集計中の値は`None`です。同じ回路を事前検証と実機実行に使う手順は[Qiskit連携ガイド](../integration/qiskit_support.ipynb)で紹介しています。

### 不具合修正

- **異なる幅のレジスタや配列を同じカーネルに渡す場合**、回路の生成と`qm.resources.logical()`によるリソース推定の両方で、呼び出しごとの幅が使われるようになりました。たとえば、行の各要素に1回ずつ回転ゲートを適用するカーネルに長さ2と3の行を順に渡すと、回転ゲート数は実際の回路でも推定結果でも合計5個になります。
- **角度の配列を使うQiskit回路**では、配列の長さがコンパイル時に決まっていれば、`row[len(row) - 1]`や`row[-1]`で末尾の要素を回転角に使えます。回路を一度コンパイルすれば、実行ごとに角度の配列を変えられます。
- **制御ビットに応じて角度を選ぶY回転**では、`uniformly_controlled_ry()`と`uniformly_controlled_ry_from_angles()`で、6個の制御ビットから64通りの角度を選ぶ回路をコンパイル・実行できるようになりました。RC1ではカーネル呼び出しの深さの上限に達することがありました。[オプション価格計算のチュートリアル](../algorithm/option_pricing.ipynb)では、価格ごとに回転角を変える例を紹介しています。
- **定数多項式のQSVT**では、RC1で1個の位相に余分な$-\pi/2$のずれが生じていました。`QSVTPhases.from_qsp_wx()`で位相を変換した場合も、`synthesize_qsvt_polynomial()`で係数から合成した場合も、制御付きQSVT回路の測定結果が変わることがありました。該当する回路は元の位相または係数から作り直してください。
- **(3,2)量子ランダムアクセス符号**（`QRACVariant.QRAC32`）で1つのグループにちょうど2変数を割り当てると、RC1ではハミルトニアン（モデルのエネルギーを表す演算子）を作る際に、その変数の係数に掛ける倍率が小さすぎました。該当するグループがある場合は、元のモデルからハミルトニアンを生成し直してください。
- **Qiskit回路を再利用する場合**、RC1では`load_circuit()`で取り出した回路のループ内に回転角を設定すると、元のコンパイル済みプログラムを後で実行したときにも、その角度が使われることがありました。正式版では実行ごとに指定した値が使われます。
- **QURI Partsの測定結果**を受け取る`QuriPartsSampler`で、基底状態とその出現回数にNumPyの整数型を使えるようになりました。RC1では、どちらかがNumPyの整数だと、正しい測定結果でも`ExecutionError`になることがありました。
- **測定結果で分岐する`if`文**では、コンパイラがどちらの分岐でも使わない定数を分岐に渡さなくなりました。これにより、`2**31`などの大きな整数定数を分岐の後で初めて使う場合に起きていたコンパイルエラーを修正しました。
