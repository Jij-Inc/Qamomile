# Qamomile v0.16.0 RC1

> **このリリースは最初のリリース候補版（RC1）です。ここに記載する仕様やAPIは、正式版までに変更される可能性があります。**

Qamomile v0.16.0 RC1では、コンパイラの中核をRustへ移し、プログラムの定義・検証・実行の仕組みを大きく見直しました。Pythonで量子プログラムを書く使い方を残しながら、v0.15.xまでのインターフェースにも広い範囲で変更を加えています。ここでは代表的な変更を紹介します。

以下のコードはv0.16.0 RC1の新しい書き方です。Qiskit Aerを使う例ではQiskit連携が必要です。後続の例では、最初に定義する`endpoint`や`program`を引き続き使います。

## Rustを中核に、プログラムのルールを検証

v0.15.xまでは、Qamomileのコンパイラ処理をPythonで実装していました。Pythonで書いた量子カーネルの構文を変換し、その関数を仮の入力で動かして操作を記録するトレーシングによって、中間表現を作っていました。

v0.16.0 RC1では、カーネルの関数本体をPythonとして実行せず、ソースコードからプログラムを組み立てます。Python側で構文解析して型付きHIR（ソースに近い中間表現）を作り、Rust側で型や量子値の使い方を検証して、QCore（Qamomile共通の中間表現）へ変換します。資源解析や実行先への変換も、この検証済みの表現を基に行います。

利用者がRustを書く必要はありません。量子プログラムは引き続きPythonで記述します。

## 定数の確定・コンパイル・実行を共通の操作へ

v0.15.xでは、`QiskitTranspiler`などのTranspilerと、Executorを組み合わせていました。

v0.16.0 RC1では、`specialize`で定数を確定し、`compile`で変換し、`run`で実行する共通の操作を使います。変換先は`compile(..., to=...)`、実行先は`run(..., on=...)`で指定します。`run`には、カーネルを直接渡して変換から実行までをまとめて任せることも、コンパイル済みのプログラムを渡すこともできます。

```python
import qamomile as qm
from qamomile.qiskit import Aer

@qm.qkernel
def biased_coin(theta: qm.Param[qm.Real]) -> qm.Shot[qm.Bits[1]]:
    state = qm.qubits(1)
    state = qm.ry(state, theta)
    return qm.measure(state)

endpoint = Aer()
program = qm.specialize(biased_coin)
artifact = qm.compile(program, to=endpoint.target)
record = qm.run(
    artifact, on=endpoint, parameters={"theta": 0.0}, shots=8, seed=7
)
counts = record.result.counts
```

値の型に加え、いつ値が確定するかも宣言します。`Const[T]`は`specialize`時、`Param[T]`は`run`（実行開始）時、`Shot[T]`は1回の試行中に決まる値です。この例の回転角は`Param`なので、コンパイル済みのプログラムを使い回し、実行ごとに角度を変えられます。

## 測定と期待値計算の入口の変更

v0.15.xでは、複数回の測定に`executable.sample()`、1回の実行やカーネル内の`expval`による期待値計算に`executable.run()`を使っていました。

v0.16.0 RC1では、測定を含むカーネルは`qm.run()`で実行し、`RunRecord`（実行条件と結果の記録）を受け取ります。上の例の`record.result.counts`が、測定値ごとの回数です。

観測量の期待値には、`qm.expectation()`を使います。測定済みの値ではなく、量子状態を準備するカーネルと観測量を渡し、推定値と標準誤差を受け取ります。`run()`の返り値が自動的に期待値へ切り替わる仕組みではありません。

```python
@qm.qkernel
def prepare_zero() -> qm.Q[qm.Bits[1]]:
    return qm.qubits(1)

estimate = qm.expectation(
    prepare_zero, qm.Z(0), on=endpoint, shots=8, seed=7
)
value = estimate.value
error = estimate.standard_error
```

## 量子型をlinearへ変更し、自動uncomputationを導入

v0.15.xでは、量子値を`Qubit`や`Vector[Qubit]`で表し、affine（同じ状態を高々1回だけ使い、未使用のまま残すことも認める規則）を適用していました。v0.16.0 RC1では、量子状態を`Q[T]`で表し、各時点の状態を返却や測定などへちょうど1回引き渡すlinearの規則をRust側で検証します。これに伴い、不要な量子状態を明示的に破棄する関数`discard`を導入しました。ただし、`discard`は明示的に破棄をするだけであり、それまでの計算を取り消して初期状態へ戻す作業ではありません。

一方で、安全に逆計算できることをコンパイラが確認できる作業用量子状態には逆操作と解放を自動的に挿入する仕組みauto uncomputation（不要になった計算を逆操作で初期状態へ戻す処理の自動挿入）も導入しました。コンパイラによりauto uncomputation可能であると確認できるケースでは、利用者は`discard`を明示的に呼び出さずとも量子値をaffineのように未使用のまま残せます。

```python
@qm.qkernel
def with_scratch() -> qm.Shot[qm.Bits[1]]:
    scratch = qm.qubits(1)
    scratch = qm.h(scratch)
    scratch = qm.t(scratch)
    return qm.measure(qm.prepare((1,)))
```

この例の`scratch`には、逆操作と解放が自動で挿入されます。すべての未使用状態が対象ではありません。外部から受け取った量子入力や、出力として残す状態とつながった作業領域などでは、返却・測定・明示的な破棄などを記述する必要があります。

## リソース推定をResourceStudyとして取得

v0.15.xの`kernel.estimate_resources()`から、v0.16.0 RC1では`qm.resources.logical(...)`へ変わります。新たな戻り値は`ResourceStudy`で、`metric()`から量子ビット数やゲート数などの指標を選びます。

```python
study = qm.resources.logical(program)
gates = study.metric(qm.resources.LOGICAL_GATES)
qubits = study.metric(qm.resources.LOGICAL_PEAK_QUBITS)
```

新しい推定結果では、値だけでなく、上下限、仮定、不明な要因を扱います。

## algorithmとstdlibの量子部品をstdlibへ統合

v0.15.xで`qamomile.circuit.algorithm`と`qamomile.circuit.stdlib`に分かれていた、再利用する量子アルゴリズムの部品と標準関数を、`qamomile.stdlib`へまとめました。QFTなどは、ここから読み込んでカーネル内で使います。

```python
from qamomile.stdlib import qft

@qm.qkernel
def fourier_sample() -> qm.Shot[qm.Bits[2]]:
    state = qm.qubits(2)
    state = qft(state, 2)
    return qm.measure(state)
```

アルゴリズム名が同じでも、引数や返り値は新しい量子型に合わせて変わっています。

## 量子操作を合成するSignalとResponseを追加

v0.15.xにはなかった、量子操作を組み合わせるための`Signal`と`Response`を追加しました。`Region`で入力・出力のビット条件を選び、その間の変換を`Signal`として扱います。積や重み付き和を構成でき、`Response`で指定した多項式により特異値（行列による伸縮の大きさを表す値）を変換する量子操作も生成できます。

以下は、先頭のビットが0となる部分を選び、特異値を半分にする変換を作る例です。

```python
import qamomile as qm
from qamomile.stdlib import Region, Response, response, select

@qm.qkernel
def transform(state: qm.Q[qm.Bits[2]]) -> qm.Q[qm.Bits[2]]:
    return qm.h(state, target=0)

signal = select(transform, input=Region("0*"), output=Region("0*"))
transformed = response(signal, Response.chebyshev([0.0, 0.5]))
```

## QSVTの位相合成と近似誤差の検証を追加

v0.15.xでもQSVT（量子特異値変換）は利用できましたが、汎用の`qsvt()`へ渡す位相列は利用者が用意していました。v0.16.0 RC1では、Chebyshev多項式（関数の近似によく使う多項式）の係数から位相列を生成する`synthesize_qsvt_polynomial()`を追加しました。合成後の応答の実部について、区間`[-1, 1]`で目標の多項式との近似誤差を検証します。返されたオブジェクトは、そのまま`qsvt()`に渡せます。

```python
from qamomile.stdlib import synthesize_qsvt_polynomial

# Approximate p(x) = 0.5 * x.
polynomial = synthesize_qsvt_polynomial([0.0, 0.5], max_error=1e-6)
assert polynomial.uniform_error_bound <= 1e-6
```

対応する多項式の偶奇や係数の大きさには制約があります。また、再構成誤差が0のblock encoding（行列を正規化して量子操作の一部に埋め込む表現）に対し、最小特異値の下限を指定して逆数関数を近似する変換を構成する`reciprocal_svt()`も追加しました。

## SciPyの疎配列からblock encodingを構成

v0.16.0 RC1では、SciPyの疎配列（非ゼロ要素を中心に保持する配列）からblock encodingを構成する`sparse_access_block_encoding()`を追加しました。v0.15.xにはなかった行列入力の方法で、`csr_array`などを直接渡せます。複素数や非対称の行列にも対応します。

```python
from scipy.sparse import csr_array
from qamomile.stdlib import sparse_access_block_encoding

matrix = csr_array([[1.0, 0.0], [0.0, 0.5]])
encoding = sparse_access_block_encoding(matrix, max_error=1e-8)
```

正規化係数は`normalization`、行列の再構成誤差の上限は`error_bound`で確認できます。

## 数理最適化をConverterからExperimentへ

v0.15.xでは、`QAOAConverter`などが問題を量子回路へ変換する操作の中心でした。v0.16.0 RC1では、`QAOAExperiment`などのExperiment（問題と設定をまとめた実験）を使います。

問題と層数を固定してコンパイルし、角度などの実行時パラメータを変えながら実行できます。次はQAOAの実行手順を示す例で、角度を探す最適化ループは含みません。

```python
from qamomile.optimization import BinaryModel, QAOAExperiment

model = BinaryModel.from_hubo({(0,): -1.0, (1,): -1.0, (0, 1): 2.0})
experiment = QAOAExperiment(model, layers=1)
compiled = experiment.compile(to=endpoint.target)
result = compiled.run(
    on=endpoint, gammas=[0.0], betas=[0.0], shots=8, seed=7
)
```

## 量子カーネルの最適化処理を追加する経路

v0.15.xにも、定数の計算や回路の置き換えなどの処理はありましたが、v0.16.0 RC1では、`OptimizationPipeline`（変換処理の組み合わせと順序を指定するもの）を`optimizer=`に渡し、最適化処理を選択・拡張できます。

```python
from qamomile.compilation import OptimizationPipeline

optimizer = OptimizationPipeline.multilevel(family=False)
optimized = qm.compile(program, to=endpoint.target, optimizer=optimizer)
```

`append()`や`replace()`などで独自の処理を追加・差し替えできます。変換したプログラムもRustの検証を通ります。ただし、型や構造の検証は、独自の変換が同じ計算結果を保つことを自動証明するものではありません。

## Cirq連携とQIRの直接出力を追加

v0.15.xからあるQiskitなどの連携に加え、Cirq向けの変換・実行を追加しました。実行先を変えても、`qm.run(..., on=...)`という呼び出し方は共通です。次の例にはCirq連携が必要です。

```python
from qamomile.cirq import CirqSimulator

cirq_record = qm.run(
    biased_coin, on=CirqSimulator(),
    parameters={"theta": 0.0}, shots=8, seed=7,
)
```

また、QIRを直接出力できます。旧版のHUGR経由のQIR対応とは別の入口です。次の例にはQIR連携が必要です。

```python
from qamomile.qir import QIR, load_ir

qir_artifact = qm.compile(fourier_sample, to=QIR())
qir_text = load_ir(qir_artifact)
```

QIRはQamomile内の実行先ではなく、外部の処理系へ渡す出力形式です。現在は回路の構造が事前に決まるQIR 1.0 Base Profileが対象で、実行時パラメータ、測定結果による分岐、測定後のゲートなどには対応しません。

v0.15.2で追加されたH2連携についてはv0.16.0 RC1では未対応です。
