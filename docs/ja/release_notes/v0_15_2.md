# Qamomile v0.15.2

Qamomile v0.15.2では、最適化問題の低エネルギー状態を選び出すQSVTによる固有状態フィルタリングアルゴリズムの提供、Nexus経由のQuantinuum H2実行、HUGRプログラム内でのショット番号の取得のサポートに対応しました。

```bash
pip install qamomile==0.15.2
```

## 破壊的変更

### Heliosへの送信時にコスト上限を指定

Heliosへの新しいジョブの送信時は、`NexusExecutionOptions`の`max_cost`に実行コストの上限を指定してください。上限が未指定の場合は、送信前にエラーになります。

### Qiskitの依存バージョンを制限

Qiskit連携の依存バージョンを`qiskit>=2.3.0,<3`に制限しました。

## 新機能

### QSVTによる固有状態フィルタリングアルゴリズムの提供

QSVT(Quantum Singular Value Transform)を用いた固有状態フィルタリングアルゴリズムを用いた`QSVTEigenstateFilterConverter`を量子最適化モジュールに追加しました。このConverterを用いることで、ユーザーは解きたい最適化問題を入力するだけで、このアルゴリズムを実現する量子回路の構築、また実行結果を入力形式に合わせて変換することができます。これによりQamomileの最適化モジュール及びアルゴリズムのサポートがさらに強化されました。

使い方は[QSVTフィルタリングによるグラフ分割問題の求解](../algorithm/qsvt_eigenstate_filter_graph_partitioning.ipynb)を参照してください。

### HUGRプログラム実行サポートの強化

以降は、HUGRでの実行に関する機能追加であるため、利用するにはhugrオプションをつけてQamomileをインストールする必要があります。

```bash
pip install "qamomile[hugr]==0.15.2"
```

#### Nexus経由でのQuantinuum H2デバイスでの実行をサポート

HUGRの実行先としてQuantinuum H2デバイスに対応しました。`HugrExecutor("nexus")`でH2を指定すると、QamomileがプログラムをQIRに変換し、ローカルで検証してから送信します。なお、H2での実行はPython 3.11と3.12のみに対応しており、Python 3.13以降には対応していないことに注意してください。

H2実機用の実行設定は次のとおりです。

```python
from qamomile.hugr import HugrExecutor, NexusExecutionOptions

executor = HugrExecutor(
    "nexus",
    options=NexusExecutionOptions(system_name="H2-1", project="qamomile-demo"),
)
```

変換済みプログラムの`sample()`にこの実行設定を渡して実行します。エミュレーターを使う場合は`system_name="H2-1E"`に変更してください。利用にはNexusアカウントと対象機器へのアクセス権が必要です。これにより、Qamomileの実行サポート範囲がさらに強化されました。なお、`system_name`にHeliosを指定することでHeliosへの送信もサポートをしていますが、実機/エミュレータの実行を伴うQamomileの実行確認はH2デバイスのみで行われていることに注意してください。

実行例は[HUGRサポート](../integration/hugr_support.ipynb)を参照してください。

#### H2の構文チェックに対応

`system_name="H2-1SC"`を指定し、ショット番号や固定長配列を使うプログラムも、実機で実行する前に構文チェックできるようになりました。`job.status()`で状態を更新すると、提供元から返されたコストも`job.metadata()`で確認できます。構文チェックでは測定結果を返さないため、`job.result()`はエラーになります。

#### H2向けQIRの取得と再利用に対応

H2向けの`sample()`や`run()`で生成したQIRを`program.qir`、送信名や実行先などの情報を`program.qir_info`で取得できるようになりました。生成済みのQIRと送信情報は、通信エラー時にも保持されます。同じ変換済みプログラムで直前と変換条件が一致する場合は、構文チェックからH2実機へ切り替える際もQIRを再利用します。QIRを再利用しても、送信は新しいジョブとして行われます。

#### ショット番号を取得する関数を追加

`qmc.get_current_shot()`で、現在のショット番号を`UInt`として取得できるようになりました。量子カーネル内で、ショットごとにゲートや固定サイズの古典的な値の一覧の要素を選択できます。

例えば、ショットごとに適用するPauliゲートを切り替えることで、Pauli twirlingなどを実装できます。また、shot毎に異なる操作を1つのプログラムにまとめて複数ショットを実行できるため、1ショットずつ別の回路を生成・送信する方法に比べて、準備や送信にかかる時間を減らし、実行の高速化が期待できます。この機能により、Qamomileの量子カーネルの記述の幅が広がり、実行サポートの強化がされました。

なお、H2デバイスへの自然な入力として[Guppy](https://docs.quantinuum.com/guppy/)を使い、Guppyの[`get_current_shot`関数](https://docs.quantinuum.com/guppy/api/generated/guppylang.std.qsystem.utils.get_current_shot.html)を利用する場合、Seleneエミュレータでは0-origin、H2デバイスでは1-originとしてショットが開始しますが、Qamomileではこの差を吸収し、両実行方法で0-originとなるようにサポートしています。

`get_current_shot()`の実行例は[HUGRサポート](../integration/hugr_support.ipynb)を参照してください。

#### H2でショット番号を使った固定長配列の参照に対応

H2向けのプログラムで、`values[qmc.get_current_shot()]`のように、ショット番号を使った固定長配列の参照に対応しました。値が確定した`UInt`または`Bit`の配列を対象に、ショット番号への非負の定数の加算・乗算にも対応します。

#### 測定結果の配列の更新に対応

繰り返し処理や条件分岐の中で測定結果の配列を書き換えられるようになりました。例えば、`old = bits[0]`で値を保存してから配列の要素を反転しても、`old`には元の値が残ります。以前は、このような配列更新を含むプログラムの変換に失敗していました。
